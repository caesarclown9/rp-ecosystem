01 Интеграция с 1С · критический · первым ~5 недель · Этап 2

RedStaff = master, 1С = потребитель.

Фиксируем в архитектуре, что источник правды по людям — RedStaff. 1С запрашивает данные по API и подписывается на события, а не хранит мастер-копию. Конец рассинхрону при смене должности и увольнении.

Что делаем
  • Фиксируем RedStaff как master-источник всех кадровых данных
  • REST API с авторизацией для 1С: табель, утверждённые заявки, статус больничных, профиль
  • Журнал интеграций + дашборд мониторинга в админ-панели
  • Регламент сопоставления записей по ПИН КР и альтернативным идентификаторам
Как технически
  • Документированный REST API + Swagger-спецификация
  • Журнал: дата, направление, статус, кол-во записей, текст ошибки
  • Политика обработки ошибок и повторных запросов
  • Расписание синхронизаций согласуется при внедрении
Что получает заказчик
  • Одна точка правды по ФИО, должности, статусу
  • 1С не нужно «допиливать» при каждом изменении в кадрах
  • HR видит, где и почему сломалась интеграция
  • Фундамент для всех остальных блоков
Дополнительно по согласованию
  • Event-driven обмен: события employee.hired / transferred / terminated в очередь, polling как fallback
  • Outbox-pattern + idempotency keys на webhook расчётного листка — без дублей
  • API versioning с первого дня (/v1, /v2) — изменения не ломают 1С
Приоритет: критическийЭтап: 2Результат: API + журнал + регламент эксплуатации
02 Расширенный профиль сотрудника ~3 недели · Этап 2

22 поля, ИП, увольнение, версионирование.

Профиль расширяется до 10 разделов с ролевой моделью доступа. Мобильный онбординг в 7 шагов, поддержка ИП-сотрудников и корректный жизненный цикл при увольнении и возврате.

Что делаем
  • Модель профиля: личные / контактные / кадровые / посещения / табель / обучение / рейтинг / документы / события
  • Мобильный онбординг 7 шагов: анкета → документы → верификация → push → передача в УЧР
  • 22 поля приёма на работу с валидациями и обязательностью
  • Категория ИП: наименование, ИНН ИП, реквизиты, срок договора, свидетельство
Как технически
  • Ролевая модель: Сотрудник / Руководитель / HR / Супер администратор
  • ПИН КР — мастер-идентификатор; паспорт + страна + разрешение для иностранцев
  • Авто-уведомления HR за 30 дней до истечения паспорта / разрешения
  • Процедура увольнения: причина, статус передачи МТС, подтверждение HR, перевод в архив
Что получает заказчик
  • Единая карточка сотрудника на всю группу
  • Прозрачный приём и увольнение без «потерянных» данных
  • Готовность к ИП/ГПХ — важно для Альфа Ойл
Дополнительно по согласованию
  • Версионирование полей: история кто / когда / почему менял должность, оклад, локацию
  • Selfie-верификация при онбординге (фото из паспорта vs selfie)
  • Импорт действующих сотрудников из 1С при миграции — без ручного ввода штата
Приоритет: высокийЭтап: 2Результат: профиль + онбординг + ролевая модель
04 Расчётный листок 1С → RedStaff ~3 недели · Этап 2

Прозрачные начисления в кармане сотрудника.

1С передаёт факт начисления через webhook, сотрудник видит расшифровку в мобильном. HR перестаёт быть «справочным бюро» по зарплате.

Что делаем
  • API-endpoint приёма (POST, авторизация по API-ключу): ПИН, период, KPI, удержания, net_salary
  • Валидация структуры и фиксация в журнале интеграций
  • Раздел «Зарплата» в моб. приложении: оклад / KPI / удержания / итог
  • Push о новом листке; хранение всех листков за всё время
Как технически
  • Idempotency на webhook — повтор не создаёт дубль начисления
  • Доступ строго к собственным листкам; чужие — недопустимо
  • Связка с табелем и профилем по ПИН
Что получает заказчик
  • Поток вопросов «почему мне начислили столько?» уходит в самообслуживание
  • Меньше трудовых конфликтов, выше доверие
  • HR работает над стратегией, не разъяснением
Дополнительно по согласованию
  • Расшифровка KPI и удержаний по основаниям
  • PDF-экспорт листка на email и в «Документы» — для банка/кредита
  • Калькулятор «что если»: пересчёт при изменении переработки/премии
Приоритет: высокийЭтап: 2Результат: раздел «Зарплата» + webhook + хранение
∞ Инфраструктура и сквозная архитектура всю Этап 2 · параллельный поток

Миграция DO → NSP без даунтайма.

Серверная часть переезжает на инфраструктуру NSP в Кыргызстане. Закладываем масштаб и наблюдаемость сразу — пока это дешевле, чем на втором году эксплуатации.

Инфраструктура
  • Миграция Digital Ocean → NSP: данные, доступы, SSL, без простоев
  • Согласование CPU / RAM / диск до старта
  • Staging-контур для UAT (изолированный subdomain, APK, TestFlight)
  • Поддержка публикации в App Store / Google Play
Сквозные предложения
  • TimescaleDB для табеля и транзакций — partitioning по времени
  • Read replica PostgreSQL для тяжёлых выгрузок и BI
  • Feature flags — выкат фич без re-deploy и безопасный rollback
  • Observability: structured logs + Prometheus + Grafana
  • Multitenancy-готовность (tenant_id) — на будущее

03 Учёт рабочего времени · СКУД + GPS ~5 недель · Этап 3

Табель из трёх источников + антифрод.

Главная боль удалённых АЗС и нефтебаз, где нет СКУД. Табель собирается автоматически из трёх источников, аномалии подсвечиваются HR.

Что делаем
  • Интеграция со СКУД — фактические приход/уход
  • Сетка табеля по дням с цветовой маркировкой типа дня
  • Кабинеты: сотрудник (свой), руководитель (сводно по подчинённым), HR (вся компания, фильтры)
  • Ручные корректировки с обязательной причиной и журналом; выгрузка XLSX/PDF
Как технически
  • Multi-source: СКУД + GPS-геофенсинг + Wi-Fi-чекин
  • Где СКУД нет — геофенсинг подменяет источник, единая модель табеля
  • Auto-close незакрытой смены через настраиваемое время
Что получает заказчик
  • Конец Excel-табелям на 200+ АЗС
  • Антифрод: одновременное присутствие в двух локациях, аномальные тайм-стампы, правки задним числом
  • Сигналы — для HR в дашборде, не для автоблокировки
Зависимость
  • Интеграция со СКУД — при наличии протокола обмена от вендора
  • Если протокол не предоставлен — GPS-геофенсинг как основной источник, без изменения стоимости

05 Рейтинговая система ~4 недели · Этап 3

Рейтинг по реальным KPI, не игра в тесты.

Базовый рейтинг по обучению расширяется до реальных операционных KPI и командных метрик. Естественный мост к премированию и бухгалтерскому контуру.

Что делаем
  • Начисление баллов: 50 за тему с тестом ≥80%, 20 за тест ≥70% (настраивается)
  • 4 уровня: Новичок / Специалист / Профессионал / Эксперт со значками
  • Рейтинги: общий, по подразделению, таблицы лидеров с фильтрами
  • Виджет на главном экране, ТОП-10 в месячной отчётности, push при переходе уровня
Что получает заказчик
  • Прозрачная мотивация линейного персонала
  • Объективная база для премий
  • Вовлечённость и снижение текучки
Дополнительно по согласованию
  • Метрики за пределами обучения: безаварийность, план продаж АЗС, NPS, дисциплина
  • Командные рейтинги: смена / АЗС / регион
  • Выгрузка для бухгалтерии — основа премирования (мост к RedLedger)
  • Бейджи и достижения (геймификация)
Приоритет: среднийЭтап: 3Результат: рейтинг + виджет + отчётность ТОП-10
06 Заявки: отпуска / больничные / ОБС / командировки ~4 недели · Этап 3

Из почты и мессенджеров — в систему с SLA.

Пять типов заявок с типизированными формами, маршрут согласования в три шага, прозрачные статусы и план отпусков с подсветкой пересечений.

Что делаем
  • 5 типов: ежегодный отпуск, ОБС, командировка, выезд по личным делам, больничный
  • Маршрут 3 шага: Сотрудник → Руководитель → HR, 7 статусов
  • Загрузка больничного (PDF/JPG/PNG, до 15 МБ, авто-сжатие)
  • Уведомления email + push на каждом изменении статуса
Как технически
  • История заявок с фильтрами и выгрузкой XLSX/PDF
  • План отпусков по подразделению/компании с автоподсветкой пересечений
  • Связка с табелем и 1С
Что получает заказчик
  • Ни одной «потерянной» заявки
  • Управляемая загрузка персонала по объектам
  • Документальный след по каждому решению
Дополнительно по согласованию
  • Доп. типы: внутренний перевод между АЗС/НБ, аванс, запрос на обучение, изменение реквизитов
  • SLA на согласование с автоэскалацией на HR при просрочке
  • Mass-actions для HR — массовое утверждение типовых заявок
Приоритет: среднийЭтап: 3Результат: workflow заявок + план отпусков
07·08 Накопленный бэклог + SSO в B2B ~3 недели · Этап 3

Закрываем долги Этапа 1 и единый вход в B2B.

Финальный блок: исполнение накопленного бэклога по утверждённому списку и единый вход в Red Petroleum B2B без повторной аутентификации.

Блок 7 · Накопленный бэклог
  • Исчерпывающий список фиксируется в Bitrix24 до старта и утверждается обеими сторонами
  • Категории: оптимизация бизнес-логики, баги (крит → высокие → средние), UX, отчётность
  • Исполняется итеративно сквозным потоком
  • При существенном превышении объёма — Дополнительное соглашение
Блок 8 · SSO в Red Petroleum B2B
  • Кнопка «Red Petroleum B2B» в моб. приложении и веб-портале
  • Переход без повторной аутентификации: OAuth 2.0 / SAML 2.0
  • Управление правом доступа супер-администратором, по умолчанию не назначен
  • Старт после согласования механизма с владельцем B2B
Что получает заказчик
  • Чистая система без накопленных дефектов
  • Единый вход для сотрудников группы
  • Готовность к подключению RedLedger и ИИ-ботов
Зависимость
  • SSO стартует только после подписания протокола согласования механизма с владельцем B2B-портала
