C.1 Документ-конвейер ~3 недели · Этап 1

Пачка документов → распознавание → 1С.

Загрузка ZIP с договорами, актами, счетами и платёжками. Конвейер инвентаризирует, классифицирует, парсит и матчит контрагентов — бухгалтер только проверяет.

Что делаем
  • Пакетная загрузка (ZIP / файлы) с инвентаризацией
  • Классификация: договор / акт / счёт / выписка / платёжка / реестр контрагентов
  • OCR + LLM-парсинг полей (контрагент, номер, дата, сумма)
  • Матчинг контрагентов по ИНН / названию / ссылке 1С
Как технически
  • Пайплайн: загрузка → инвентаризация → классификация → извлечение → матчинг → проверка → превью 1С
  • Статусы партии: uploaded → ready_for_review → completed
  • Оригиналы хранятся неизменно, с контрольной суммой и MIME
  • Уровни уверенности + причины «заблокировано»
Что получает бухгалтер
  • Кабинет проверки: вкладки Файлы / Контрагенты / Банки / Договоры / Ошибки
  • Bulk-действия: назначить контрагента / счёт / исключить / в импорт
  • Кратно меньше ручного ввода первички
Принцип безопасности
  • Документы НЕ проводятся напрямую — только после проверки бухгалтером
  • В 1С — сначала dry-run превью, потом подтверждённый экспорт
Этап: 1Результат: рабочий конвейер первички с кабинетом проверки
C.2 Банковские выписки ~2 недели · Этап 1 (параллельно)

Импорт, авто-категоризация, сверка.

Выписки кыргызских банков загружаются в любом формате, нормализуются, категоризируются и сверяются с операциями и контрагентами. Конец сверке в Excel.

Импорт
  • Форматы PDF / XLSX / CSV + generic-парсер под банки КР
  • LLM-fallback для нестандартных форм выписок
  • Нормализация и дедупликация строк
  • Несколько счетов и юрлиц
Сверка
  • Авто-категоризация по правилам и истории
  • Сопоставление строк с контрагентами и транзакциями
  • Подсветка нераспознанного — на ручную проверку
  • Импорт в транзакции после подтверждения
Что получает заказчик
  • Сверка выписок — минуты вместо дней
  • Видно нераспознанные/спорные строки
  • Единая картина по всем счетам группы
Этап: 1Результат: авто-импорт и сверка банковских выписок
C.3 Двусторонняя 1С + пилот ~3 недели · Этап 1

Dry-run → подтверждение → выгрузка в 1С.

Интеграция с вашей 1С через OData и webhook. Проверенные документы идут как превью, и только подтверждённое выгружается — с идемпотентностью и журналом. Пилот на одном юрлице.

Интеграция
  • Подключение к 1С: OData + HTTP-сервис / webhook-мост
  • Синхронизация справочников контрагентов
  • Очередь синхронизации + повтор + журнал обмена
  • Шифрование учётных данных 1С
Как технически
  • Idempotency keys на каждую сущность — повтор не создаёт дубль
  • Dry-run / outbox: кандидаты-payload сохраняются, пушится только подтверждённое
  • Сверка результата выгрузки с 1С
Пилот на 1 юрлице
  • Альфа Петролеум — оптовый контур (договоры, акты, сверки)
  • Обучение бухгалтеров кабинету
  • Замер baseline-метрик до и после
Зависимость
  • Нужен доступ к вашей конфигурации 1С и включённый OData / HTTP-сервис
Этап: 1Результат: рабочая связка с 1С + пилот на 1 юрлице

C.6 Связки экосистемы + SSO ~3 недели · Этап 2

Финансовый контур в единой экосистеме.

RedLedger перестаёт быть отдельным продуктом: получает данные от других модулей, единый вход и общую ролевую модель. Деньги встают рядом с людьми и процессами.

Входящие потоки данных
  • RedStaff → ФОТ, премии по рейтингам
  • ИИ-юрист → карточки договоров и контрагентов
  • ИИ-тендеры → кредиторка и платежи; ИИ-сметы → capex-бюджет
  • RedCharge / RedPay → выручка ЭЗС и лояльности
Единый доступ
  • SSO с RedStaff — один логин на экосистему
  • Ролевая модель: owner / admin / бухгалтер / менеджер / наблюдатель + права + доступ к проектам
  • Telegram-кабинет в одном канале с остальными модулями
Что получает заказчик

  • Один вход, одна модель прав, один источник правды поверх 1С
  • AI-ассистент по данным компании (поиск, ответы, сводки)
